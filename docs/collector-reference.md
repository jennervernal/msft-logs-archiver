# Collector reference

| Collector | API/module and data | Retention relevance | Permission | Paging/window behavior | Limits and expected status |
|---|---|---|---|---|---|
| `EntraAudit` | Graph `v1.0/auditLogs/directoryAudits`; directory changes and administrative audit events | A3/P1 commonly 30 days | `AuditLog.Read.All` plus directory reader/security role | Sequential `@odata.nextLink`, adaptive half-open windows, native `id` dedupe | Required by example; permission/license/API errors fail |
| `EntraSignIns` | Graph `v1.0/auditLogs/signIns`; interactive/non-interactive sign-in records returned by API | A3/P1 commonly 30 days | `AuditLog.Read.All` plus reporting/security role | Graph paging, page max 1000, adaptive windows, native `id` | Some fields depend on role/license; required by example |
| `EntraRiskySignIns` | Same sign-in endpoint, filtered locally for risk state/levels | Full risk detail generally needs P2 | Same scope/role as sign-ins | Same paging; throws when risk fields are `hidden` | Optional by example; may be `optional-failed` under A3 |
| `UnifiedAudit` | ExchangeOnlineManagement `Search-UnifiedAuditLog`; AuditData JSON across Exchange, SharePoint, OneDrive, Teams, Entra, and integrated workloads | Audit Standard commonly 180 days | Audit Logs/View-Only Audit Logs; Purview role as applicable | Stable `SessionId`, `ReturnLargeSet`, max 5,000/page, bounded 50,000/session behavior, recursive split | Serialized only; required by example; dense minimum window fails explicitly |
| `IntuneAudit` | Graph `v1.0/deviceManagement/auditEvents`; Intune administrative audit actions | Portal commonly 1 year; Graph commonly up to 2 years | `DeviceManagementApps.Read.All` plus Intune/RBAC audit read | Graph paging, max 100/page, adaptive windows, native `id` | Requires active Intune entitlement; required by example |
| `AzureActivity` | ARM `Microsoft.Insights/eventtypes/management/values`; subscription control-plane events | Platform retention commonly 90 days | Azure Reader/Monitoring Reader/custom read action | Per-subscription source, ARM `nextLink`, adaptive windows, `eventDataId`/`id` dedupe | Empty subscription list discovers visible enabled subscriptions; none visible is fatal |
| `DefenderXdr` | Graph `security/runHuntingQuery`; configured advanced-hunting tables | Product/table retention varies by Defender entitlement | `ThreatHunting.Read.All` plus Defender RBAC/table access | Table-specific KQL, limit-plus-one, bounded buffer and recursive split | Capability check can yield `skipped-unavailable`; optional by recommendation |

Collectors preserve returned object fidelity. They do not enrich records with tenant, subscription, or table labels; source directory names identify subscription/table boundaries. All date windows are semantically half-open. UAL adapts its inclusive cmdlet end by one .NET tick.

Zero-configuration mode selects the first five collectors only. No visible enabled Azure subscription produces `skipped-unavailable`. A 404 from the Intune audit endpoint produces `skipped-unavailable`; empty but available Intune data is a successful empty partition. Authentication/authorization failures are not treated as absence and remain nonzero failures.
Native retention is the time Microsoft keeps data at the source, not the suite's local retention. Licensing, service configuration, and Microsoft policy can alter availability. Verify the current official documentation before planning a backfill; see [retention reference](retention-reference.md).
